# 신답 경제 게임랩

초등학생이 직접 기획한 경제 게임 4종을 웹으로 옮긴 STEAM 수업용 웹앱입니다.
사회 「경제 활동과 물건의 교류」 단원과 연결됩니다.

원본 기획서: `data/20260727120138.pdf` (16쪽, 게임 1개당 4쪽)
분석 문서: `extracted_games.md`

## 이 앱의 핵심 — 기획 평가와 디버깅

기획서에 적힌 **숫자를 그대로** 구현했습니다. 그래서 몇몇 게임은 그대로 두면 클리어가 아주 어렵거나
아무리 열심히 해도 돈이 늘지 않습니다. 그게 이 수업의 재료입니다.

1. 학생이 게임을 플레이한다
2. 게임 화면 오른쪽 위 **AI 한줄평**을 읽는다 — 왜 잘 안 되는지 한 문장으로 짚어 준다
3. 상단 **📋 기획 평가**를 열어 자기 기획이 항목별로 어떻게 평가됐는지 확인한다
4. 평가서의 **디버깅 목록**에 적힌 순서대로 직접 계산해 본다
5. 고칠 숫자를 **얼마로 정할지 결정**해서 학습지에 적는다
6. 교사가 그 값을 `js/games/*.js` 의 `paramSpec` 기본값에 반영하고 다시 배포한다

### 게임 안에 숫자 조절 기능을 넣지 않은 이유

학생이 만든 게임은 **그 게임을 기획한 학생이 정한 값 하나**로만 돌아가야 한다고 보았습니다.
언제든 슬라이더로 만질 수 있으면 게임이 작품이 아니라 설정 화면이 되고, 기획자의 결정권이 희석됩니다.
초4에게 슬라이더 8~10개는 무엇을 만질지 찾는 탐색 비용도 큽니다.

슬라이더 UI(조절실) 코드는 지우지 않고 `index.html` · `js/core.js` · `js/boot.js` 세 곳에 주석으로 남겨 두었습니다.
필요하면 세 블록의 주석을 함께 풀면 됩니다.

값을 바꾸려면 각 게임 파일 맨 위 `paramSpec` 의 `orig` 만 고치면 됩니다. 예를 들어 의자 팔기의 판매가는
`js/games/chair.js` 의 `{ key: 'sellPrice', ... orig: 1000 }` 한 줄입니다.

### AI 기획 평가서 (`review.html`, 앱 안에서는 📋 버튼)

게임을 실제로 만들고 테스트해 본 결과를 근거로, 네 게임을 **같은 6개 항목**으로 평가합니다.
판정은 ○ 그대로 좋음 / △ 다듬으면 좋음 / ✕ 고쳐야 함 세 가지입니다.

| 항목 | 무엇을 보는가 |
|---|---|
| 규칙이 분명한가 | 읽고 바로 게임으로 옮길 수 있는가 |
| 목표에 닿을 수 있는가 | 수업 시간 40분 안에 끝낼 수 있는가 |
| 돈이 도는가 | 버는 돈이 쓰는 돈보다 많은가 |
| 고를 거리가 있는가 | 매번 같은 행동만 반복하지 않는가 |
| 실패할 수 있는가 | 긴장하게 만드는 위험이 있는가 |
| 경제 개념이 들어갔는가 | 사회 시간에 배운 내용이 규칙에 담겼는가 |

평가서에는 이어서 **기획서에 없어서 구현자가 정한 값**(학생이 되찾아야 할 결정)과,
**디버깅 목록**(1·2순위 문제 + 테스트에서 나온 수치 + 고치는 단계 3~5개)이 붙습니다.

게임별 판정 집계는 다음과 같습니다.

| 게임 | ○ | △ | ✕ | 1순위 문제 |
|---|---|---|---|---|
| 의자 팔기 | 3 | 2 | 1 | 이익이 0원이라 장사가 의미 없음 |
| 햄버거 가게 | 3 | 1 | 2 | 목표 금액이 너무 커서 끝이 안 남 |
| 타이쿤 | 4 | 1 | 1 | 목표 1억에 비해 자동차 값이 쌈 |
| 물건을 사고 파는 가게 | 5 | 1 | 0 | 어떤 물건이 이득인지 게임이 안 알려 줌 |

## 게임 목록

| # | 게임 | 기획 | 기획서 원문 승리 조건 | AI 한줄평 요지 |
|---|---|---|---|---|
| 1 | 의자 팔기 | 탕탕이 | 3회 반복 | 재료값 1,000원 = 판매가 1,000원이라 수익이 0원 |
| 2 | 햄버거 가게 | 개미핥기 | 24776만원 | 버거 3,000원으로 2억 4천만원은 약 8만 개 |
| 3 | 타이쿤 | 에라이!! | 1억 원 | 자동차 50만원 × 200대, 그동안 배고픔은 계속 줄어듦 |
| 4 | 물건을 사고 파는 가게 | 이상한 사람들 | 400초 / 30개 / 5000코인 | 사과만 팔면 안 됨, 비싼 특산물(옷)을 노려야 함 |

각 게임 화면의 **📄 기획안 보기**를 누르면 학생이 직접 그린 원본 스캔 4쪽을 볼 수 있습니다.
스캔본에는 실명 없이 모둠 닉네임만 들어 있습니다.

## 조작

- 마우스·터치로 모든 조작이 가능하고, 키보드 단축키가 버튼 오른쪽에 표시됩니다
- 공통: `Esc` 창 닫기 / 대시보드로
- 게임 1: `Enter` 진행, `Space` 망치질, 도둑은 직접 눌러서 잡기
- 게임 2: `Q` 채소 `W` 고기 / `1~4` 재료 쌓기 / `F` 감튀 `C` 콜라 / `Enter` 대접
- 게임 3: `1` 판매 `2` 수리 `3` 마트 `4` 식당 `5` 옷 갈아입기 `6` 잠자기 `7` 여행
- 게임 4: `1~4` 마을 이동 / `B` 사기 / `Enter` 가장 비싼 물건 팔기

## 실행

정적 파일만 있으면 됩니다. 빌드 도구·프레임워크 없음.

```
python -m http.server 8777
```
브라우저에서 `http://localhost:8777`

Vercel에 그대로 올리면 됩니다 (빌드 설정 없음, 루트가 그대로 배포 대상).

## 화면

- 학생 크롬북 16:9 / 교사 전자칠판 기준. 대시보드·게임 화면 모두 세로 스크롤 없음
- 게임 화면은 좌(상태) · 중앙(무대) · 우(조작) 3분할

## 기획서에 없어서 임의로 정한 값

원문에 수치가 없던 항목만 채웠습니다. 모두 각 게임 파일의 `paramSpec` 에서 바꿀 수 있습니다.

- 게임 2 시작 돈 5,000원 — 첫 고기를 살 수 있어야 진행되므로
- 게임 2 밥값 3,000원 / 옷값 8,000원, 하루 손님 5명
- 게임 3 자동차 값 50만원, 부속 10만원, 수리비 20만원, 여행 30만원, 배고픔 감소 2/초
- 게임 4 시작 코인 500, 특산물은 자기 마을에서 정가의 절반, 다른 마을은 1.0~1.8배 (10초마다 변동)
